# 1. Service Explanation: GCP Cloud Storage

## What is Cloud Storage?
Google Cloud Storage (GCS) is an **Object Storage** service. It is the direct equivalent of **AWS S3**.
*   **Bucket:** The container for your data (similar to a folder in the cloud).
*   **Object:** The actual file stored inside the bucket (e.g., images, videos, logs).
*   **Naming:** Unlike AWS (where it is just S3), in GCP and Azure, the service is often referred to as "Storage" or "Blob Storage," but the concepts of "Bucket" and "Object" remain the same.

## Key Characteristics
1.  **Unlimited Storage:** You can store unlimited data in a bucket. There is no limit on the total size of the bucket.
2.  **Object Limit:** A single object (file) can be up to **5 TB** in size.
    *   *Note:* The speaker mentioned AWS increased its limit to 50 TB, but GCP is currently capped at 5 TB.
3.  **Durability:** It provides **99.999999999% (11 9's)** durability. This means your data is extremely safe; it will not be lost.
4.  **Global Access:** While buckets are physically located in specific regions, the dashboard is global. You can access and manage buckets from anywhere in the world via the GCP Console.

# 2. Step-by-Step & Storage Classes (Deep Dive)

GCP organizes data into **Storage Classes** based on how frequently you access the data. Choosing the right class optimizes cost.

### A. Standard Storage (Hot Storage)
*   **Usage:** For data that you access frequently (e.g., daily or multiple times a month).
*   **Cost:** Highest cost per GB.
*   **Performance:** Fastest access and lowest latency.
*   **Pricing Example (India):** Approx. ₹1.8 - ₹3.6 per GB/Month (approx. $0.043 mentioned in audio).
*   **Default:** This is the default class if you don't specify anything.

### B. Nearline Storage
*   **Usage:** For data that you access infrequently (less than once a month).
*   **Use Cases:** Monthly backups, disaster recovery snapshots, old logs.
*   **Cost:** ~50% cheaper than Standard Storage.
*   **Retrieval Cost:** There is a data retrieval fee (approx. $0.01 per GB) when you access the data.
*   **Minimum Duration:** You must store data here for at least **30 days**.
    *   *Early Deletion Penalty:* If you delete the data before 30 days, you will still be charged for the full 30 days.

### C. Coldline Storage
*   **Usage:** For data that you rarely access (less than once every 3 months).
*   **Use Cases:** Compliance archives, long-term backups.
*   **Cost:** Cheaper than Nearline and Standard.
*   **Retrieval Cost:** Higher retrieval fee (approx. $0.02 per GB).
*   **Minimum Duration:** You must store data here for at least **90 days**.
    *   *Early Deletion Penalty:* You pay the remaining fees if deleted before 90 days.

### D. Archive Storage
*   **Usage:** For long-term data retention (store and forget). Used once a year or less.
*   **Cost:** Lowest storage cost.
*   **Minimum Duration:** **365 days**.
    *   *Early Deletion Penalty:* Significant penalty if deleted within a year.
*   **Key Difference (vs AWS Glacier):** The speaker highlighted that even though it is Archive storage, you get **instant access (milliseconds)**. Unlike AWS Glacier where retrieving data might take hours, GCP Archive provides instant retrieval.

# 3. Missing Points & Advanced Features for Beginners

### Bucket Location Types (Unique to GCP)
When creating a bucket, you must choose a location. Unlike AWS where you just pick a region and enable replication, GCP offers distinct types:

1.  **Regional:**
    *   Data is stored in a specific region (e.g., `asia-south1` Mumbai).
    *   **Use Case:** When you need low latency for users in that specific area.
    *   **Cost:** Lowest.

2.  **Dual-Region:**
    *   Data is automatically replicated in two specific regions within the same geographic area (e.g., Mumbai + Hyderabad).
    *   **Use Case:** For High Availability (HA) and Disaster Recovery (DR). If one region goes down, the other has the data.
    *   **Note:** Google chooses the partner region automatically based on the primary region selected.

3.  **Multi-Region:**
    *   Data is replicated across multiple regions within a large geographic boundary (e.g., `Asia` or `EU`).
    *   **Use Case:** Global content delivery where you need high availability across an entire continent.
    *   **Cost:** Highest cost due to storage and data transfer fees.

### Access Control
1.  **IAM (Recommended):** Use the same IAM roles (Storage Viewer, Storage Admin) to control who can access the buckets.
2.  **ACLs (Legacy):** Access Control Lists. An older method to give specific users permission to specific files. Generally recommended to avoid ACLs and stick to IAM for security.

### Tools to Access Storage
1.  **Console:** The web UI.
2.  **Cloud Shell:** A browser-based terminal.
    *   Command: `gsutil` (this is the specific command for GCP Storage, similar to `aws s3`).
    *   Example: `gsutil cp file.txt gs://my-bucket/`

# 4. Comparison: AWS S3 vs. GCP Cloud Storage vs. Azure Blob Storage

Here are the critical differences between the three major cloud providers for object storage, tailored for interviews.

| Feature | AWS S3 | GCP Cloud Storage | Azure Blob Storage |
| :--- | :--- | :--- | :--- |
| **Service Name** | Simple Storage Service (S3) | Cloud Storage | Blob Storage (part of Storage Account) |
| **Container Name** | Bucket | Bucket | **Container** |
| **Object Name** | Object | Object | **Blob** |
| **Storage Classes** | Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier Deep Archive | Standard, Nearline, Coldline, Archive | **Hot, Cool, Archive** |
| **Object Limit** | Up to **5 TB** (supports >5TB via multipart). | Up to **5 TB** (Hard limit). | Up to **~4.75 TB** (per blob). |
| **Archival Access** | **Glacier Deep Archive:** Retrieval takes hours (3-12 hours). | **Archive:** Instant retrieval (milliseconds). | **Archive:** Retrieval takes hours (requires "rehydration"). |
| **Redundancy Setup** | **Cross-Region Replication (CRR):** Requires manual rule setup between buckets. | **Bucket Types:** Native Regional, Dual-Region, and Multi-Region options. | **Account-Level:** LRS, ZRS, GRS, GZRS configured on the Storage Account. |
| **Commands** | `aws s3 cp ...` | `gsutil cp ...` | `az storage blob upload ...` |
| **Pricing UI** | Requires a pricing calculator to estimate. | Console shows pricing estimates dynamically. | Pricing Calculator required; estimates not shown during creation. |

# 5. Interview Cheat Sheet: Key Differences (Expanded)

**Q: What is the terminology difference between the three providers?**
*   **AWS & GCP:** Both use the term **"Bucket"** for the top-level container.
*   **Azure:** Uses the term **"Container"** (and "Blob" for the file). This is a classic interview question to see if you know the Azure vocabulary.

**Q: Which cloud provider offers "Instant" archival data retrieval?**
*   **GCP:** Only GCP offers **instant retrieval** (milliseconds) for Archive storage.
*   **AWS & Azure:** Both require hours (rehydration) to retrieve data from their deepest archive tiers (Glacier/Archive).

**Q: How do the Storage Classes map across AWS, GCP, and Azure?**
*   **Frequent Access:** AWS Standard = GCP Standard = Azure Hot.
*   **Infrequent Access (Monthly):** AWS Standard-IA = GCP Nearline = Azure Cool.
*   **Rare Access (Quarterly):** AWS Glacier Flexible Retrieval = GCP Coldline = Azure Cool (or Archive depending on duration).
*   **Long-term/Compliance:** AWS Glacier Deep Archive = GCP Archive = Azure Archive.

**Q: How does data replication differ across providers?**
*   **AWS:** You create a bucket in one region. To replicate elsewhere, you must create a destination bucket and manually configure a "Replication Rule" (CRR).
*   **GCP:** You choose the **redundancy topology** (Regional, Dual-Region, Multi-Region) *when you create the bucket*. Google handles the replication logic automatically.
*   **Azure:** You configure redundancy (LRS, ZRS, GRS) at the **Storage Account level**, not the container level. All containers within that account inherit the replication settings.

**Q: What is the command-line tool equivalent for Azure?**
*   **AWS:** AWS CLI (`aws`).
*   **GCP:** Cloud SDK (`gsutil`).
*   **Azure:** Azure CLI (`az`).
