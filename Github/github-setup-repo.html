  3. Name it: repo-access-setup

# ? Paste token → PASTE YOUR TOKEN HERE

SEGMENT 4

.gitkeep — Making Git Track Empty Folders

4.1

The Problem: Git Ignores Empty Folders

🚫 Critical Issue: If you run git add . right now, Git will say "nothing to commit" because Git only tracks FILES, not empty directories!

# This will FAIL — "nothing to commit"
git add .
git commit -m "add folders"
# ❌ nothing to commit, working tree clean
4.2

The Solution: Add .gitkeep to Every Empty Folder

# Add .gitkeep to ALL empty directories
find . -type d -empty -exec touch {}/.gitkeep \;

# Verify .gitkeep files were created
find . -name ".gitkeep"

# Now add and commit — THIS WILL WORK ✅
git add .
git status
# ✅ Shows all .gitkeep files as "new file"

💡 What is .gitkeep? It's a convention (not a Git feature). It's an empty file whose only purpose is to force Git to track the parent directory. Name it .gitkeep so its purpose is self-documenting.

GitHub Actions — CI Workflow

7.1

Create Repository Hygiene Workflow

This CI pipeline automatically checks that required files exist and the repo structure is maintained on every PR.

# .github/workflows/repo-hygiene.yml
name: Repository Hygiene Check

on:
  pull_request:
    branches: [ main ]
  push:
    branches: [ main ]

jobs:
  hygiene:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Check required files exist
        run: |
          REQUIRED_FILES=(
            "README.md"
            "LICENSE"
            ".gitignore"
            ".github/CODEOWNERS"
            ".github/SECURITY.md"
            ".github/SUPPORT.md"
            "src/client/.gitkeep"
            "src/server/.gitkeep"
            "k8s/qa/.gitkeep"
            "k8s/prod/.gitkeep"
            "terraform/.gitkeep"
            "scripts/.gitkeep"
            "docs/.gitkeep"
          )
          MISSING=0
          for file in "${REQUIRED_FILES[@]}"; do
            if [ ! -f "$file" ]; then
              echo "❌ MISSING: $file"
              MISSING=1
            else
              echo "✅ EXISTS: $file"
            fi
          done
          if [ $MISSING -eq 1 ]; then
            echo "::error::Required files are missing!"
            exit 1
          fi

      - name: Check for large files
        run: |
          # Find files larger than 5MB
          LARGE=$(find . -type f -size +5M -not -path "./.git/*")
          if [ -n "$LARGE" ]; then
            echo "::error::Large files detected:"
            echo "$LARGE"
            exit 1
          fi
          echo "✅ No large files found"

SEGMENT 10 — CRITICAL

Rule Sets & Branch Protection

🚨 This is the MOST IMPORTANT segment. Without rule sets, anyone can force-push to main, delete the repo, or merge without review. This is what separates a toy repo from an enterprise repo.

10.1

Navigate to Rule Sets (Not Legacy Branch Protection)

💡 Modern approach: Use Rule Sets (not the older "Branch protection rules"). Rule Sets are the modern, more powerful replacement. Path: Settings → Rules → Rulesets → New ruleset → New branch ruleset

  1. Go to your repository on GitHub
  2. Click Settings tab
  3. In left sidebar, click Rules → Rulesets
  4. Click "New ruleset" → "New branch ruleset"
  5. Name it: main-branch-protection
  6. Set Enforcement status to Active
  7. Under Target branches, select "Include default branch"
10.2

Configure ALL 6 Protection Rules

Enable each rule one by one in the ruleset configuration:

1
Require a Pull Request before merging
  • ✅ Enable the toggle
  • ✅ Required approving reviews: 1
  • ✅ Allowed merge methods: ONLY "Squash merge" (disable create merge commit & rebase)
2
Require status checks to pass
  • ✅ Enable the toggle
  • ✅ Search and add: hygiene (from our CI workflow)
  • ✅ Enable "Require branches to be up to date before merging"
3
Require linear history
  • ✅ Enable — prevents merge commits, keeps history clean
4
Require signed commits
  • ✅ Enable — only GPG/SSH signed commits can be pushed to main
5
Block force pushes
  • ✅ Enable — prevents git push --force which rewrites history
6
Restrict deletions (if available)
  • ✅ Enable — prevents anyone from deleting the main branch
10.3

Bypass List — Keep It EMPTY

⚠️ Important: The bypass list lets specific people skip all rules. Leave it EMPTY or limit to maximum 1-2 trusted admins. In enterprises, even admins follow the PR process. The more people on the bypass list, the weaker your security.

10.4

Test: Verify Protection Is Active

# Switch to main and try direct push (SHOULD FAIL)
git checkout main
echo "test" >> README.md
git add README.md
git commit -m "test: direct push attempt"
git push origin main

# ❌ EXPECTED ERROR:
# "remote: error: GH006: Protected branch update failed for refs/heads/main."
# "remote: error: push declined due to repository rule violation"

# ✅ This confirms your rule set is WORKING!

# Clean up the test commit
git reset --hard HEAD~1
git checkout core-repo-scaffold

✅ If you see the "push declined" error — CONGRATULATIONS! Your repository is now protected. Direct pushes to main are blocked forever.
